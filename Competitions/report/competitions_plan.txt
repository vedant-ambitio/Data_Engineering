  6) DATA SOURCES — RESEARCHED & VERIFIED (REVISED April 2026)
================================================================================

  KEY FINDING: No single platform aggregates high school competitions well.
  Unlike college students (who have unstop.com with 500+ listings), school
  students (class 8-12) have NO dedicated competition aggregator.

  THREE VIABLE SCRAPED SOURCES:

    Source                     Total    HS eligible  Domains
    -------------------------  -------  -----------  -------
    devpost.com                200-300  26           Coding/hackathons ONLY
    studentcompetitions.com    23       ~5           All domains (but tiny)
    dublieu.com                7        ~3-4         Mixed (art, writing, essay)

  Combined scraping yield: ~35 HS competitions.
  35 is not enough. And 26 of those are coding-only from devpost.
  For STEM, Writing, Art, Business, Environment, Social Impact —
  these platforms give almost nothing.

  SOLUTION: TWO-LAYER APPROACH (Scrape + Gemini Discovery)
  ─────────────────────────────────────────────────────────

  LAYER 1 — AUTOMATED SCRAPING (3 sources, weekly refresh)

    Source                  Method                   HS Yield   Refresh   Domains
    ----------------------  -----------------------  ---------  --------  -------
    devpost.com             GitHub scraper            ~26       Weekly    Coding only
                            (Metruption/hackathon-
                            scraper) + search filter
                            "high school"
    studentcompetitions.com Static HTML, 3 pages      ~5        Weekly    All (tiny)
                            Filter: education=HS
    dublieu.com             Static HTML               ~4        Weekly    Mixed
                            Filter: School Students
    ----------------------  -----------------------  ---------  --------  -------
    SUBTOTAL (Layer 1)                                ~35       Weekly

    devpost data quality is excellent (28-30/33 fields per hackathon):
      - name, organizer, deadline, prizes, eligibility, judging criteria,
        submission format, themes — all on one page
      - All free (no paid registration issue)
      - Pre-built GitHub scrapers exist
      - Each hackathon has its own subdomain (hackamerica.devpost.com)

    studentcompetitions & dublieu are thin but give non-coding competitions
    (art, writing, essay, business) that devpost doesn't have.


  LAYER 2 — GEMINI DISCOVERY (per domain, monthly refresh)

    Same pattern as Summer Schools discover_programs.py:
    Ask Gemini (web-grounded) for each of the 7 UI domains.

    Prompt per domain:

       [STEM / Business / Coding / Writing / Arts / Environment / Social Impact].

       eligibility, mode (online/offline), cost (free/paid).
       Only list competitions you are confident exist — no fabrication."

  SHARED PIPELINE (both layers feed into this)
  ─────────────────────────────────────────────

  STEP A: GEMINI EXTRACTION
    For each competition's raw text:
      → Send to Gemini with 33-field schema prompt
      → Get structured JSON back
      → Tag with source (devpost / studentcompetitions / dublieu / gemini_discovery)

  STEP B: DEDUPLICATE
    Same competition may appear in both layers:
      "Conrad Challenge" on dublieu (Layer 1) + Gemini discovery (Layer 2)

    Dedup logic:
      → Match by competition name (fuzzy) + organizer
      → If duplicate, MERGE: keep version with more fields filled
      → Priority: Official page > devpost > Layer 1 scraped > Gemini basic
      → Result: one record per competition with best data

  STEP C: VALIDATE & FILTER
    → Remove competitions with deadline in the past
    → Remove paid registration > INR 2,000 / USD 25
    → Remove college-only (not open to class 8-12)
    → Check required fields (name, domain, deadline)
    → Map domain to UI enum (STEM / Business / Coding / Writing / Arts /
      Environment / Social Impact) — Gemini does this from tags

  STEP D: SAVE OUTPUT
    competition_data/
      raw/                    ← one JSON per competition (UI-ready)
        conrad-challenge.json
        isef-2026.json
        hackamerica.json
        ...
      qa/                     ← QA sidecar per competition
      _summary.json           ← batch stats (total, per-source, coverage)
      _duplicates.json        ← log of merged duplicates


  REFRESH SCHEDULE:
  ─────────────────

    Weekly (Layer 1):
      1. Re-scrape devpost / studentcompetitions / dublieu
      2. Compare with existing:
         New → add, Updated deadline → update, Expired → mark "closed"
      3. Gemini extract only for new/changed competitions
      4. ~15 min automated

    Monthly (Layer 2):
      1. Re-run Gemini discovery for all 7 domains
      2. Diff against existing data:
         New competitions → add (scrape + extract)
         Removed → flag for removal
         Same → no action
      3. Content team reviews ONLY the diff (~10-20 changes)
      4. ~1-2 hours (automated + review)


--------------------------------------------------------------------------------
  SCRIPT STRUCTURE
--------------------------------------------------------------------------------

  TWO SCRIPTS (not one unified scraper):

  1) competition_scraper.py (Layer 1 — weekly)
     │
     ├── fetch_devpost()        → GitHub scraper + "high school" search
     │                            scrape each subdomain page
     │                            returns list of raw competition dicts
     │
     ├── fetch_studentcomp()    → static HTML, 3 pages, HS filter
     │                            returns list of raw competition dicts
     │
     ├── fetch_dublieu()        → static HTML, School Students filter
     │                            returns list of raw competition dicts
     │
     ├── gemini_extract()       → 33-field schema extraction
     │
     ├── deduplicate()          → fuzzy name match, merge best fields
     │
     ├── validate_and_filter()  → remove expired, paid, college-only
     │
     └── save_output()          → write raw/ + qa/ + summary

  2) discover_competitions.py (Layer 2 — monthly)
     │
     ├── discover_by_domain()   → Gemini web-grounded per domain
     │                            (same pattern as discover_programs.py)
     │
     ├── validate_urls()        → HTTP HEAD check, homepage detection
     │
     ├── scrape_official()      → fetch each competition's official page
     │
     ├── gemini_extract()       → 33-field schema extraction
     │
     ├── merge_with_existing()  → diff against current competition_data/
     │
     └── save_output()          → write raw/ + qa/ + summary

  CLI usage:
    python competition_scraper.py                  # Layer 1 weekly scrape
    python competition_scraper.py --source devpost # one source only
    python discover_competitions.py                # Layer 2 full discovery
    python discover_competitions.py --domain STEM  # one domain only
