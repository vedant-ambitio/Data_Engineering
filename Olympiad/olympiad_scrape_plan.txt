================================================================================
  4) RECOMMENDED SCRAPING STRATEGY (REVISED — GENERIC GEMINI-BASED SCRAPER)
================================================================================

  PHILOSOPHY:
  -----------
  Reuse the proven architecture from the university pipeline:
    Script 1 (structured_data_extraction.py)  → Gemini extraction from text
    Script 2 (merge_course_data.py)            → Merging multiple sources

  Apply the SAME pattern to olympiads:
    olympiad_scraper.py  → Fetch HTML from multiple sources (Tier 1 → 2 → 3)
                            → Strip to text → Send to Gemini with 35-field schema
                            → Output markdown + JSON with inline citations

  Why this is better than 30 hardcoded scrapers:
    - One generic scraper handles all olympiads
    - Gemini handles unstructured/varying HTML layouts naturally
    - Reuses 80% of existing code (auth, rate limiting, retry logic, prompt patterns)
    - Adding a new olympiad = 1 line in URL config, not new code
    - Same pattern as university extraction (proven on 8,000+ files)

--------------------------------------------------------------------------------
  PHASE 0: URL CONFIG (one-time setup)
--------------------------------------------------------------------------------

  Build a single config file: olympiads_urls.json

  Format:
    {
      "IMO": {
        "name": "International Mathematical Olympiad",
        "tier1_urls": ["https://www.imo-official.org/", "https://www.imo-official.org/year_info.aspx?year=2026"],
        "tier2_urls": ["https://en.wikipedia.org/wiki/International_Mathematical_Olympiad"],
        "tier3_urls": ["https://www.lumiere-education.com/post/12-olympiads-for-high-school-students"],
        "search_query": "International Mathematical Olympiad 2026 deadline registration"
      },
      "INMO": { ... },
      ...
    }

  Effort: ~2 hours to compile URLs for all 30 olympiads

--------------------------------------------------------------------------------
  PHASE 1: GENERIC SCRAPER (olympiad_scraper.py)
--------------------------------------------------------------------------------

  For each olympiad in olympiads_urls.json:

    STEP 1 — Discover (optional, smart updates)
      - WebSearch query → find newer URLs missed by config
      - Append discovered URLs to fetch list

    STEP 2 — Fetch (Tier 1 first, fall back to Tier 2/3)
      - Try requests + BeautifulSoup (fast, ~80% of sites work)
      - On failure (timeout, JS-rendered, blocked):
          → Fall back to Puppeteer MCP (browser-rendered)
      - Strip HTML to plain text
      - Tag each page with source URL for citation tracking
      - Concatenate all sources into one context

    STEP 3 — Extract via Gemini
      - Same auth/calling logic as structured_data_extraction.py
      - Strict prompt with 35-field schema
      - Rules: only extract what's in the text, null for missing,
        cite source URL per field, no hallucination
      - Output: structured JSON

    STEP 4 — Save outputs
      - olympiads/raw/IMO.json       (structured 35 fields)
      - olympiads/markdown/IMO.md    (human-readable with inline citations)
      - olympiads/qa/IMO_qa.json     (per-field source tracking)

    STEP 5 — Quality check
      - Required fields filled? (name, deadline, official URL, eligibility)
      - Mark missing required fields for manual review
      - Flag suspicious values (deadline in past, cost > Rs 10,000)

--------------------------------------------------------------------------------
  PHASE 2: PUPPETEER FALLBACK (only when needed)
--------------------------------------------------------------------------------

  Most olympiad sites are static HTML — plain HTTP works:
    - HBCSE TIFR              → static
    - IMO Official            → static
    - SOF World               → static
    - Wikipedia               → static
    - Aggregator sites        → static

  Puppeteer needed only for:
    - IOAI registration form  (JS-rendered)
    - IEO interactive pages   (dynamic content)
    - Sites with anti-bot     (need real browser headers)

  Use Puppeteer MCP only as fallback after HTTP fails.

--------------------------------------------------------------------------------
  PHASE 3: GEMINI EXTRACTION PROMPT (key design)
--------------------------------------------------------------------------------

  Prompt structure (similar to structured_data_extraction.py):

    SECTION 1 — Critical rules
      - Extract ONLY what's in the source text
      - Null for missing fields, never guess
      - For each field, capture which source URL it came from
      - For dates, use YYYY-MM-DD; if year missing, use upcoming cycle
      - Multi-stage olympiads: capture parent_olympiad field

    SECTION 2 — 35-field schema (same as Section 1 of this report)

    SECTION 3 — Sources (concatenated text from all fetched URLs)
      [SOURCE 1: https://imo-official.org/]
      ... text ...
      [SOURCE 2: https://en.wikipedia.org/wiki/IMO]
      ... text ...

  Gemini returns structured JSON with citations:
    {
      "activity_name": {"value": "International Math Olympiad", "source": "SOURCE 1"},
      "deadline": {"value": "2026-04-10", "source": "SOURCE 1"},
      "eligibility": {"value": "...", "source": "SOURCE 2"},
      ...
    }

--------------------------------------------------------------------------------
  PHASE 4: MARKDOWN OUTPUT FORMAT
--------------------------------------------------------------------------------

  Same pattern as university markdowns — sections + inline citations.
  Example olympiads/markdown/IMO.md:

    # International Mathematical Olympiad (IMO)

    ## Overview
    The IMO is the most prestigious mathematics competition for high school
    students worldwide, established in 1959.

    <citation>
    status: verified
    urls:
    - https://en.wikipedia.org/wiki/International_Mathematical_Olympiad
    </citation>

    ## Eligibility
    Open to high school students under 20 years of age...

    <citation>
    status: verified
    urls:
    - https://www.imo-official.org/general_regulations.aspx
    </citation>

    ## Deadline
    April 10, 2026 (Indian national qualification deadline)
    July 10-21, 2026 (international competition in China)

    <citation>
    status: verified
    urls:
    - https://secure.hbcse.tifr.res.in/ino/
    - https://www.imo-official.org/
    </citation>

    ... and so on for all sections

--------------------------------------------------------------------------------
  PHASE 5: ANNUAL REFRESH
--------------------------------------------------------------------------------

  Just rerun olympiad_scraper.py:
    - Same script, same URLs
    - Gemini re-extracts with current page content
    - Updates dates, deadlines automatically
    - Diff old vs new JSON to flag what changed

  Schedule: November (before next academic cycle starts)
  Time: ~30 minutes for all 30 olympiads
  Manual review: ~2 hours by content team

--------------------------------------------------------------------------------
  PHASE 6: DAILY DEADLINE TRACKER (separate, lightweight)
--------------------------------------------------------------------------------

  No scraping needed — just compute urgency chip from stored deadline:
    - More than 30 days away → "Open"
    - 7-30 days away → "Closing soon"
    - 0-7 days → "Last chance"
    - Past → "Closed"

  Cron job runs daily, updates the urgency_chip field in DB.

================================================================================
  7) RISKS & MITIGATIONS
================================================================================

  Risk                                Mitigation
  ----------------------------------- -------------------------------------------
  Gemini hallucinations               Strict prompt: "extract only from text,
                                      null for missing, never guess"
                                      Same approach proven on 8,000+ universities
  Rate limits                         30 olympiads is well within Vertex limits
                                      (~12 req/sec safe at 60 workers)
  Site layout changes                 Gemini handles layout variations naturally
                                      Re-run scraper picks up new format
  Multi-stage olympiads               Add parent_olympiad field to schema
  (RMO → INMO → IMO)                  Link records via short_code reference
  Year confusion (2026 vs 2027)       Prompt rule: "use most recent upcoming cycle"
  Anti-bot blocking                   Puppeteer fallback with real browser headers
  Aggregator data outdated            Tier 1 (official) takes priority
                                      Tier 2/3 only fill gaps
  Cost (Gemini API calls)             ~30 calls/year × ~$0.01 each = $0.30/year
                                      Negligible

--------------------------------------------------------------------------------
  5 IMPROVEMENTS IMPLEMENTED
--------------------------------------------------------------------------------

  Improvement 1: SMART HTML EXTRACTION
    What:   Extract <main> / <article> content only, strip <nav>, <header>,
            <footer>, <aside>, cookie/popup/sidebar divs by class/id.
    Why:    Reduces ~60% noise in source text. Gemini sees cleaner input.
    Where:  _extract_main_content() + html_to_text()

  Improvement 2: SOURCE PRIORITY LABELS
    What:   Each source tagged in prompt as:
            [SOURCE 1 — OFFICIAL — HIGHEST PRIORITY: url]
            [SOURCE 2 — REFERENCE — TRUSTED: url]
            [SOURCE 3 — AGGREGATOR — USE ONLY TO FILL GAPS: url]
    Why:    Gemini explicitly knows which source to trust for conflicts.
    Where:  process_olympiad() prompt builder

  Improvement 3: POST-EXTRACTION VALIDATION
    What:   After Gemini returns JSON, automatically check:
            - Dates not in past (flags wrong year/cycle)
            - Age limit math correct (birth year → age check)
            - Rounds reasonable (1-10, not 50)
            - Cost reasonable (< 10K for an olympiad)
            - Required fields present (name, subject, level, deadline)
    Why:    Catches errors Gemini makes. Warnings go to QA sidecar only.
    Where:  validation block after JSON parse, before save

  Improvement 4: STRONGER PROMPT RULES (12 rules, up from 10)
    What:   Added rules:
            - Rule 4: Explicit trust hierarchy with examples
            - Rule 5: Date cycle extrapolation (past dates → next cycle)
            - Rule 6: parent_olympiad = short code only (not full name)
            - Rule 10: Student-facing cost (not school/delegation cost)
            - Rule 11: rounds = THIS exam only (not multi-stage chain)
            - Rule 12: structure_format = both exam format AND broader chain
    Why:    Fixed IMO rounds=6 bug, INMO parent="IMO" not full name,
            cost shows student fee not delegation fee.
    Where:  EXTRACTION_PROMPT rules section

  Improvement 5: URL CAP (reduce noise)
    What:   Max 6 URLs total per olympiad.
            All Tier 1 (official) + all Tier 2 (reference) always included.
            Tier 3 (aggregator) fills remaining slots only.
    Why:    8-9 URLs = too much conflicting info. 6 is the sweet spot.
    Where:  process_olympiad() URL collection

--------------------------------------------------------------------------------
  EXECUTION SEQUENCE (per olympiad, with improvements)
--------------------------------------------------------------------------------

  Step 1: Load config
    - Read olympiads_urls.json
    - Get olympiad name + Tier 1/2/3 URL lists

  Step 2: Collect URLs [IMPROVEMENT 5]
    - All Tier 1 + All Tier 2 kept
    - Tier 3 fills remaining slots up to max 6 total
    - Prevents noise overload

  Step 3: Fetch URLs via HTTP
    - urllib.request with browser User-Agent
    - 30-second timeout per URL
    - Detect encoding: HTTP header → meta charset → UTF-8 fallback

  Step 4: Clean HTML [IMPROVEMENT 1]
    - Extract <main> or <article> content (skip nav/footer/sidebar)
    - Strip cookie/popup/ad divs by class/id pattern
    - Remove <script>, <style>, remaining tags
    - Decode HTML entities via html.unescape()
