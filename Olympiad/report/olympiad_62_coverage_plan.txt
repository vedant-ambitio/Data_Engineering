WHY 62? — THE FINAL NUMBER

  62 olympiads cover every major olympiad available online for grades 8-12
  students — across all 3 levels (International, National, School), all
  subjects in the PDF spec, and both entry routes. No significant olympiad
  that a student would search for is missing from this list.

  - 35 covers major subjects but leaves filters EMPTY for History, Geography,
    Philosophy, Linguistics. Launching with empty filters feels broken.
  - 50 fills every subject filter — good baseline.
  - 62 adds the "easy Phase 2" items (CREST, AI/tech, IAPT, board-adjacent)
    so we don't need a manual update for 6-12 months.
  - State-level olympiads are EXCLUDED (regional sites, fragmented, hard to
    scrape) — they're a separate project if needed later.
  - Running 62 through the scraper = ~31 minutes. Same effort as 50.

  Rule of thumb per filter:
    Every subject filter should show AT LEAST 2-3 olympiads so users don't
    hit a dead end. Every level filter (International/National/School)
    should have 10+ olympiads.

  Maintenance: Rerun scraper once per year in November. No manual update
  needed between annual runs.

================================================================================
  SCRAPER EXECUTION SEQUENCE (per olympiad)
================================================================================

  Step 1: Load config
    - Read olympiads_urls.json
    - Get olympiad name + Tier 1/2/3 URL lists

  Step 2: Auto-crawl subpages from official sites
    - For each Tier 1 URL, fetch homepage and extract internal links
    - Score links by keyword relevance (registration, eligibility, dates, etc.)
    - Add top 3 subpages to Tier 1
    - SKIP subpage crawling for JS-heavy sites (SOF, Silverzone, etc.)

  Step 3: Collect URLs [IMPROVEMENT 5]
    - All Tier 1 (with subpages, capped at 6) + All Tier 2 kept
    - Tier 3 guaranteed at least 2 slots (aggregator data is important)

  Step 4: Fetch URLs via HTTP, Puppeteer fallback for JS-heavy sites
    - Try plain HTTP first (urllib.request, 30s timeout)
    - If HTTP returns < 2000 chars AND domain is JS-heavy
      (sofworld.org, silverzone.org, unifiedcouncil.com, crestolympiads.com):
      --> Launch headless Chrome via Puppeteer (Node.js subprocess)
      --> Wait for JS rendering (networkidle2 + 3s)
      --> Extract document.body.innerText
      --> Use whichever source (HTTP or Puppeteer) gave more text
    - Result: SOF pages go from 500 chars (HTTP) to 7,000+ chars (Puppeteer)

  Step 5: Clean HTML [IMPROVEMENT 1]
    - Extract <main> or <article> content (skip nav/footer/sidebar)
    - Strip cookie/popup/ad divs by class/id pattern
    - Decode HTML entities, fix mojibake
    - Truncate to 8KB per source

  Step 6: Tag sources [IMPROVEMENT 2]
    - Source 1 --> "OFFICIAL — HIGHEST PRIORITY"
    - Source 2 --> "REFERENCE — TRUSTED"
    - Source 3 --> "AGGREGATOR — USE ONLY TO FILL GAPS"

  Step 7: Build Gemini prompt [IMPROVEMENT 4]
    - Today's date + olympiad name
    - 12 strict rules (trust hierarchy, rounds = this exam only,
      student-facing cost, date extrapolation, short codes)
    - 35-field JSON schema
    - Tagged source texts

  Step 8: Call Gemini (Vertex AI, gemini-2.5-flash)
    - Auth: JWT from dashboard/gcp-key.json
    - ~20-35 seconds response time

  Step 9: Parse JSON response

  Step 10: Validate [IMPROVEMENT 3]
    - Check dates not in past
    - Check age limit math
    - Check rounds reasonable (1-10)
    - Check cost reasonable (< 10K)
    - Check required fields present
    - Warnings go to QA sidecar only (not in raw JSON)

  Step 11: Save 4 outputs
    - raw/X.json         (CLEAN 35 fields — no _sources, no _notes --> for UI)
    - markdown/X.md      (human-readable with inline <citation> blocks)
    - qa/X_qa.json       (field_sources, extraction_notes, validation_warnings)
    - sources/X_sources.txt (raw scraped text — audit trail)

  Step 12: Summary
    - Print success/fail counts, total time
    - Save _summary_TIMESTAMP.json
